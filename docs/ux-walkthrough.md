# 体验走查与优化 · 0.2.0

本轮围绕“首次使用是否清楚、每天处理是否方便、误点能否纠正”进行模拟。没有替任何真实抖音账号发送消息，也没有把模拟结果当作微信真机结果。

## 已完成的改动

| 模拟场景 | 发现的断点 | 本轮修改 |
| --- | --- | --- |
| 首次添加好友 | 保存后返回清单，容易以为通知已经开启 | 保存后进入该任务的提醒选择，明确“只保存清单不会自动通知”；可以返回清单或暂不设置 |
| 每天处理多项 | 无文字的小圆圈容易误触，含义不够明确 | 改为“查看处理步骤”和“确认已完成”两个文字按钮；主要操作保证44px最小高度 |
| 误点确认 | 需要寻找变更后的任务再撤销 | 显示刚才操作，可直接撤销；仍保留记录页撤销 |
| 复制招呼文案 | 用户可能误认为已经替其发送 | 复制成功显示“尚未发送”；页面列出手动处理步骤；编辑文案后清除旧复制提示 |
| 反复添加同一好友 | 重复任务造成重复清单 | 新建时检查同平台同名任务，包括暂停任务；允许用户明确选择仍然添加 |
| 修改提醒时间／暂停 | 手机日历仍保存原日程，可能重复或错时 | 根据本机添加线索提示去日历单独核对；始终不声称已同步系统日历 |
| 搜索无结果／全部暂停 | 缺少下一步入口 | 增加清除搜索筛选、查看暂停任务入口 |
| 查看无记录的日期 | 容易将“没有确认”理解成“平台没完成” | 明确二者区别，并提供返回今日清单的入口 |

## 验证方式

Node自动化验证页面事件和持久化行为；浏览器预览使用同一份页面逻辑和源模板，模拟导航、弹窗、复制与本地存储。实测浏览器演练中的创建、确认、即时撤销、复制反馈，以及375px／320px布局与长名称换行。原生picker、隐私授权、微信通知、手机日历及真实抖音状态需要后续真机测试。

## 下一阶段可增加的功能

| 优先级 | 功能 | 具体价值与范围 |
| --- | --- | --- |
| 优先 | 好友分组＋批量改时间 | 好友多时按分组管理，一次调整多条任务；已有系统日历仍需单独维护 |
| 优先 | 今日跳过 | 临时不处理一天，不记成完成，也不暂停后续日期；需要云提醒同步识别跳过状态 |
| 其次 | 提醒结果中心 | 查看发送提交／失败／不确定／缺少授权，结果不等于已读；仅显示当前用户数据 |
| 其次 | 确认日历 | 按月查看本工具的手动确认情况；不冒充抖音实际火花连续天数 |
| 其次 | 数据导出与恢复 | 更换设备前备份，导入时检查版本、重复任务和日期；不会自动迁移系统日历 |
| 后续 | 双方各自授权的共同提醒 | 用户邀请对方加入，各自选择提醒；不能替对方授权或自动发消息催促 |

以上为候选功能，尚未写入0.2.0；本轮没有把安卓独立自动化App纳入小程序实现。
