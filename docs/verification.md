# 验证记录 · 0.3.1

验证日期：2026年10月30日（0.3.0验证于10月26日）。当前交付为可导入的原生微信小程序工程，默认本地模式；没有注册或登录微信账号，没有部署云环境，没有真实发送消息或创建手机日历。

## 已完成

在 Node.js 24 环境执行 `npm test`：**73项测试全部通过**。使用内存存储和模拟微信接口验证，不接触真实账号数据。

覆盖重点：

- 北京时间零点、闰日、非法日期与时间、超长输入。
- 持久化、磁盘保存失败、损坏数据保护、暂停与软删除、历史名称快照。
- 页面事件串联：新建、编辑、搜索、完成、记录撤销、暂停后找到恢复入口。
- 快速切换日期时旧响应不覆盖新结果，跨日旧页面不错误写入昨日。
- 复制文案不改变完成状态，取消删除不丢任务，失败后按钮恢复。
- 未配置提醒不弹授权、不显示虚假的发送成功；语音接受结果兼容。
- 取消日历不调用系统；已写入日历但本机记录失败不诱导再次添加。
- 云API使用可信OPENID隔离；伪造用户字段被拒绝；并发确认幂等。
- 清空中断后的写入保护及恢复；并发提醒去重；无授权线索／暂停／删除／已确认任务不发送。
- 不确定发送结果不自动重试，跨日不补发昨日提醒，SDK事务结果适配。

执行 `npm run check`：JS语法、JSON解析、8个WXML标签闭合与事件处理器、页面文件及tabBar配置检查通过。这是工程静态检查，不能替代微信的WXML编译器。

0.3.0新增覆盖：工作日／自选星期／暂停到期，置顶排序，汇总合并与免打扰，多个每周日历中途取消后补齐，复制任务不覆盖原对象；断网编辑、回执丢失及本机回执保存失败的重试，换账号不串缓存，多设备冲突和清空后的旧队列隔离；两位用户加入／独立确认／退出／清空，第三人加入限制，邀请轮换／过期，共同任务创建去重与请求标识冲突，零点期间共同确认的日期一致。

## 导入后的验收顺序

先在本地模式新建一个抖音任务和一个微博任务，重编译后确认仍在；完成一项并到记录页撤销；暂停一项后从设置恢复；编辑时间并核对详情。然后按云部署说明配置自己的测试环境和获准模板，最后验证真机通知与日历。
